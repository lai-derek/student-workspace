# Session review

Use the active conversation and observed files and results. If earlier context is missing, disclose the limit; timestamps alone do not reconstruct a session.

Reconstruct the task from the requested outcome through major decisions and revisions to the delivered artifact. For application work, trace application context, draft answers, narrative refinement, and completion; adapt the stages to the actual task. Identify what each transition needed to preserve: current intent, selected evidence, protected wording, open questions, deadline, and destination. A successful save establishes delivery, not user acceptance or persuasive quality.

Review user corrections, clarified metrics, voice preferences, promised artifacts, validation findings, repeated searches, and unnecessary questions. Check whether a correction reached the current profile, catalog, relevant records, and affected drafts without modifying preserved sources.

For iterative writing, compare the user's initial purpose, accepted passages, later corrections, and delivered draft. Look for the central question being diluted, factual specificity being replaced by abstractions, and tone becoming uniform across edits. For recipient-specific writing, compare relevant recipient cues with available personal records, including useful interests and plans outside the main career topic. Distinguish a missed connection from a missing fact; do not make the user supply information the workspace already has. Preserve unresolved differences between newer self-report and dated records rather than silently rewriting either.

For material findings, give an observed example, practical consequence, likely cause and confidence, owning record/skill/code path, and smallest useful correction with an observable check. Classify causes where useful: missing evidence, missed retrieval, framing, expression, handoff, conflicting instructions, or failure to follow adequate guidance. Distinguish already corrected issues, unresolved defects, and proposed but untested changes. Do not inflate a routine audit into a report with empty categories.

Audit the cost of the process itself. Check repeated reads, unnecessary questions, optional reader rounds, duplicate final checks, and delivery delayed after a deadline warning. More review is useful only when its findings change the artifact. When asking the user to diagnose wording, show bounded excerpts from the actual current draft rather than requiring recall. Treat summaries and earlier success labels as dated interpretations; compare them with later corrections and inspectable outcomes.

For computational artifacts, reconcile the selected variant with the function or interface actually used, and distinguish a fitted candidate from an adopted model. Check that experiments described in notes have inspectable evidence and distinguish local validation, saved cloud outputs and a fresh execution. Reconcile the latest conversational corrections with compiled packets and indexes; preserve superseded versions instead of presenting pending-work text as current.

For opportunity-related application work, inspect the supplied request, official references, and relevant tool-generated reports only as needed. Preserve user-controlled submission and outcome fields. Do not recreate the old board, feed bridge, research journal, or scheduled workflow.

Apply improvements only when requested and supported by an observed problem. Prefer correcting an existing record or workflow over adding another system. Workspace instructions and tool changes require explicit permission. Do not update persistent memory without a direct user request or infer rejection from no response.

Recheck changed content and run `student-workspace audit` when source or reference integrity is affected. For skill edits, run the skill-creator validator and inspect referenced files. Report material changes and measured savings only when available; do not equate shorter prose with billed-token savings.
