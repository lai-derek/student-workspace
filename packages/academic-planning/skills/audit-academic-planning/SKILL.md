# Audit Academic Planning

Improve decision quality, efficiency, and cohesion together. Use this skill for requested audits or workflow improvements, not proactively during ordinary planning. An audit request is read-only. An explicit request to implement findings authorizes those changes within its scope; do not ask again merely because this skill normally audits. Follow the workspace's current instructions and ownership conventions.

## Bound the review

Start with the named question or artifact; otherwise review the current conversation and directly relevant files. Expand to broader history or a system review only when requested or when a concrete unresolved finding requires it. State the scope and evidence limits briefly. Missing conversation history is a limitation, not evidence that a step never happened.

Reuse available reads and findings. Follow the affected evidence chain instead of loading every planning skill, record, or historical report. Keep one compact working evidence ledger in context: claim or incident, source and observation time, consequence, and uncertainty. Do not create a report, database, exports, or persistent ledger merely to conduct the audit.

Apply the same efficiency standard to the audit itself: request bounded relevant excerpts, reuse successful reads and known failed routes, and narrow truncated output rather than reloading whole files. Stop expanding an issue when another lookup would not change its finding or proposed repair.

## Evaluate the planning

Trace consequential issues through user intent, evidence, reasoning, recommendation, and recorded state. Use the dimensions relevant to the request:

- **Effectiveness:** Did the work answer the actual question and preserve tentative preferences and explicit choices? Keep preference, degree progress, readiness, schedule feasibility, and enrollment likelihood distinct. Check consequential prerequisites, credit recognition, linked sections, conflicts, workload, downstream offerings, absence terms, and displaced coursework. Compare complete alternatives over the affected horizon without requiring a full degree audit for every question. For efficiency claims, hold desired learning/courses and existing credit fixed; distinguish total future work from additional work relative to a named baseline, including desired courses outside requirement slots. Challenge weak academic reasoning, but do not repeatedly reopen informed user decisions without new evidence.
- **Efficiency:** Did research, tools, questions, delegation, and artifacts materially improve the decision? Distinguish productive exploration and negative findings from duplicated retrieval, poor source ordering, oversized outputs, avoidable retries, unnecessary persistence, and requests for information already available. Match workflow size to the question. Do not remove verification merely to reduce tool calls.
- **Cohesion:** Do the conversation, source evidence, owning academic records, schedule data, generated views, and external planner agree within their respective dates and scopes? Distinguish proposals, selected plans, saved schedules, enrollment, completion, and approved credit. Check stale summaries, competing sources of truth, missing handoffs, broken references, and contradictory instructions. Do not create another student profile or treat a dated difference as a contradiction automatically.

Use authoritative evidence appropriate to each fact. For UCLA seats, prefer current authenticated MyUCLA when accessible; public counts can lag. Catalogs and department schedules serve different purposes. Refresh only facts that materially affect the finding. A seat snapshot supports remaining capacity, not a measured probability of future availability. Distinguish evidence for course access from evidence for academic preparedness.

Before calling record maintenance wasteful, inspect the instructions and the durable information gained. Authorized or required writes are not permission violations; propose a smaller compliant workflow if the cost was disproportionate. Before flagging stale generated views, establish whether the changed information belongs in their consumed inputs. A retained tentative recommendation need not populate final-selection fields or trigger a rebuild.

## Find the cause and propose a repair

Validate the most consequential findings against actual messages, tool results, or artifacts. Follow additional evidence only when it could change the conclusion. If the evidence supports fewer findings, return fewer findings; do not fill a quota.

Distinguish missing guidance, conflicting guidance, failure to follow adequate guidance, stale evidence, and tool limitations. Separate observed causes from hypotheses. If adequate guidance was ignored, repair the affected result and validate execution before proposing more instructions. Change guidance when a specific ambiguity or omission explains why following it could still produce the failure. A useful exploration is not waste just because its option was rejected.

For each material finding, give the concrete incident, consequence, cause and confidence, then the smallest useful correction, its owning skill/tool/record, expected benefit or tradeoff, and a proportional validation method. Prefer repairing the owner over adding overlapping workflows. Preserve checks needed for correct academic decisions. Do not modify files, memory, settings, or external applications during an audit unless the user separately requests those changes.

When implementation is requested, correct current records while preserving historical sources, user choices and tentative status. Update dependent summaries only where affected and rebuild only when consumed inputs change. Validate the correction and use a focused scenario trial for a substantive workflow change; report remaining limits rather than treating schema checks as proof of better reasoning.

## Report proportionately

Lead with the most consequential findings. Rank costs qualitatively when useful, marking inferred cost or causal claims as INFERRED and giving their basis. Include what worked when it prevents an inappropriate simplification. Separate fixes already verified from proposed changes. For a clean review, give a short result and remaining limits; no mandatory report artifact.

Report raw input, cached input, output, and reasoning tokens separately only when telemetry exposes them. Do not equate tool-output length, context size, or text reductions with billed tokens, subscription usage, or demonstrated savings. Usage percentages require directly exposed telemetry. Structural validation does not prove improved behavior; propose focused scenario trials for substantive workflow changes.

Use delegation only when a bounded independent review materially improves the audit. Give analysts compact, non-overlapping questions and avoid repeating their work at the root. No mandatory analyst chain or agent count.
